## 当前结构和运行方式

- `src/main.ts`：唯一启动入口，默认后台；`--cli` 启动终端。
- `src/server.ts`：本地 HTTP、SSE、静态资源、模型和会话接口。
- `src/cli.ts`：终端命令和交互。
- `src/config/models.ts`：模型配置；`paths.ts`：项目根目录路径定位。
- `src/agent/agent.ts`：工具调用主循环。
- `src/agent/model-stream.ts`：模型请求和 SSE 读取；`prompt.ts`：默认提示词和工具协议；`tool-call.ts`：XML 解析。
- `src/agent/session.ts`：加载历史、读取当前助手、执行一轮对话，成功后保存并记录日志。
- `src/agent/context.ts`：最近完整轮次筛选；`router.ts`：规则模型路由；`logger.ts`：Node 彩色执行日志。
- `src/tools/index.ts`：注册 `get_weather`、`read_file`、`write_file`、`edit_file`，顶层只放注册入口和工具实现。辅助文件 `types.ts`、`validation.ts`、`syntax-check.ts`、`weather.data.ts` 放在 `src/tools/utils/`。
- `src/http/`：请求响应辅助、静态资源白名单、聊天 SSE 与超时；`src/config/model-store.ts`：模型增删改和密钥过滤。
- `src/storage/sqlite.ts`：会话保存、读取、删除，以及助手模板、当前助手选择持久化。
- `admin/`：后台页面；`tests/`：测试。
- `admin/browser-runtime.js`：静态演示/浏览器直连，使用访客浏览器缓存和虚拟文件工具；静态共享代码由 `scripts/build-static.mjs` 生成。

`npm start`、`npm run dev`、`npm run main` 均启动后台，访问 `http://127.0.0.1:3000`；`npm run cli` 启动终端。

配置和数据仍在项目根目录：`.env`、`.data/models.json`、`.data/chat.sqlite`。保存的模型配置优先于环境变量；没有 `.env` 且没有 MODELS 时使用 `.env.example`。

`npm run build:static`（或 `npm run publish`）仅生成 `dist/`，`npm run preview:static` 在 4173 端口预览。静态版本不使用服务器 SQLite 或模型 Key，默认模拟回复，可切换浏览器直连。详见 [静态版本说明](STATIC_DEMO.md)。

## 当前行为

- 仅保留直接执行流程，Plan 模式已按用户要求移除，不要自行恢复。
- 已删除模式选择、计划展示与确认、终端模式命令、后端模式参数与检查、会话状态读取和计划测试。
- 打开旧数据库时自动移除废弃的 `state` 列，保留历史消息及更新时间。
- `readOnly` 保留为工具清单的能力标记，不再用于模式限制，也不是权限系统。
- 模型通过自定义 XML `<tool_call name="名称"><params>...</params></tool_call>` 调用工具，正文可使用 CDATA；解析后转换成 `{ tool, params }`。尚未使用模型原生 tool_calls。
- Agent 将所有注册工具名称与 description 注入提示词；实际执行由 execute 完成。
- 工具中间消息标记 internal，保留在模型上下文但不显示为聊天气泡。系统提示每次单独注入。
- 整轮成功后保存历史，失败不保存本轮；工具已产生的副作用不会自动回滚。
- HTTP 支持同会话并发保护、超时和断开取消。
- `GET /api/tools` 从工具注册表提供名称、说明和只读标记，页面自动展示，新增工具无需改前端清单。
- 助手回复使用 Marked + DOMPurify 渲染 Markdown，用户消息保持纯文本；原始文本保存在数据库。
- 等待时显示“正在思考”，后面的点按 1、2、3 个循环；工具执行时显示相应状态。
- 发送按钮旁有“清空上下文”，经 confirm 确认后删除当前会话并回到新对话。
- 每条消息有删除按钮并要求 confirm。删除提问会连同该轮回复和隐藏工具记录一起删除；删除回复会同时删除此前相邻的隐藏工具记录，保留提问。SQLite 消息有稳定 id，旧消息自动补齐；接口为 `DELETE /api/sessions/:id/messages/:messageId`。生成期间禁止删除。失败轮次未落库，只删除前端临时消息。删除记录不会撤销已执行的文件写入等操作。
- 后台文字至少 16px，保留更大的标题。

### 近期已实现

- 2026-10-21：Node 网页和 CLI 增加单次 Reflection。`agent.ts` 缓冲初稿，在无工具调用分支用同一模型复查，再只展示和保存最终答案。复查禁止工具调用、支持取消；页面显示复查状态，后台用黄色日志标记。默认开启，`runAgent` 可传 `reflect: false` 关闭；静态适配层暂未加入。

- 上下文按最近 3 轮完整历史和当前轮筛选，完整历史继续保存；尚无 token 预算、摘要或长期记忆。
- 模型路由支持手动/规则自动开关，不是另一个模型进行分类；每轮选定后工具循环不换模型。
- 助手配置存 SQLite，默认工具助手，支持图书管理助手、自定义新建、编辑和切换；CLI 支持 `/prompts`、`/prompt ID`。图书业务工具尚未开发。
- 工具失败即时显示错误卡片并回填 LLM，不立即终止；模型或整轮失败另行处理。页面支持停止和失败后等待计时。
- 左侧新增“工具扩展”菜单；浏览器直连顶部显示模型与请求目标，自动路由后显示实际地址。
- 天气工具从本地地区表查 ID，只请求一次文档 HTTP 接口，直接返回原始天气对象；不额外查 ID、不做复杂数据转换。真实连通性尚未验证成功。
- 后台彩色日志包含请求 ID、步骤、模型决策、工具参数、结果摘要、耗时与完成/错误状态，不是模型内部思考。完整执行轨迹的页面回放与文件差异仍未实现。
- 静态演示不联网，天气为虚构样例；直连只支持兼容 Chat Completions 的接口。Key 只留在页面内存，文件工具为虚拟文件，需考虑 CORS 和浏览器本地网络权限。
- 尚未接入 LangChain、RAG、MCP、图书 CRUD；讨论过这些概念不代表已实现。

## 已知问题与工具开发现状

- 用户已添加 write_file 和 edit_file。write_file 校验参数，原样写入并检查 JavaScript 语法，再返回检查错误供模型修复；edit_file 要求原文唯一匹配后替换，尚不检查语法。两者均未限制工作目录或确认覆盖，尚不自动创建父目录。
- 现有读写工具具有进程的文件访问权限，尚无统一授权机制。
- 工具协议已由 JSON 改为 XML，代码正文使用 CDATA，不能再要求其中的内容进行 JSON 转义。Windows 路径优先使用 `/`。
- 本地模型仍可能生成不合法的工具调用；解析失败可能作为普通回答展示。后续可讨论格式验证、错误反馈与有限重试，不能仅靠 description 保证可靠调用。
- 生成代码的正确性和格式由模型输出决定；write_file 应原样保存，不应随意删除空格“修复”。

### 作品定位与演示任务

作品：**能参考项目规范、修改代码并检查结果的本地开发助手**。

固定演示任务示例：

核心链路：定位文件 → 检索相关规范 → 读取现有代码 → 局部修改 → 检查结果 → 展示修改及来源。

### 第 1 天：工作目录边界、文件列表和搜索

- 验收：能找到目标文件、读取并局部修改；目录外访问明确拒绝，普通合法路径不受影响。

### 第 2 天：工具执行记录与修改结果展示

- 学习重点：可观察性、Agent 的行动与结果反馈、界面与后端事件协作。

### 第 3 天：最小 RAG，检索项目规范
